# Лабораторная работа №1. Простой HTTP-сервер на Node.js

HTTP-сервер на встроенном модуле `http`, без сторонних библиотек и фреймворков. Сервер возвращает текст и JSON
по нескольким маршрутам, отвечает статусом 404 на неизвестные адреса и выводит в терминал журнал запросов.

**Автор:** Иордатий Игнат, группа IA2403

## Цель работы

Познакомиться с основами серверной разработки на Node.js: создать HTTP-сервер, разобрать метод и URL запроса,
сформировать ответ с нужным кодом состояния и заголовками, вернуть данные в формате JSON и вести журнал запросов.

## Технологии

Node.js (встроенный модуль `http`). Сторонних зависимостей нет, поэтому `npm install` не нужен.

## Установка и запуск

```bash
npm start
```

или

```bash
node app.js
```

Сервер запускается на `http://localhost:3000`. Остановить его можно сочетанием `Ctrl+C`.

## Маршруты

| Метод | URL | Content-Type | Код | Ответ |
|---|---|---|---|---|
| GET | `/` | text/plain | 200 | приветствие |
| GET | `/about` | text/plain | 200 | описание лабораторной работы |
| GET | `/student` | text/plain | 200 | имя, фамилия и группа студента |
| GET | `/api/student` | application/json | 200 | объект с данными студента |
| GET | `/time` | text/plain | 200 | текущая дата и время |
| GET | `/api/courses` | application/json | 200 | массив из трёх курсов |
| GET | `/random` | text/plain | 200 | случайное число от 1 до 100 (собственный маршрут) |
| любой другой | любой другой | text/plain | 404 | `404 - Page not found` |

Строка запроса (`?...`) отбрасывается перед сравнением маршрута, поэтому `/student?x=1` отвечает так же, как `/student`.

## Как устроен код

1. **Создание сервера.** `http.createServer((req, res) => { ... })` принимает функцию-обработчик, которая вызывается
   на каждый запрос. Объект `req` содержит метод (`req.method`) и адрес (`req.url`), объект `res` служит для формирования
   ответа. `server.listen(PORT)` начинает прослушивать порт 3000.
2. **Логирование.** Первой строкой обработчика, до выбора маршрута, в терминал выводится запись о запросе.
   Поэтому в журнал попадают и запросы, закончившиеся ошибкой 404.
3. **Маршрутизация.** Из `req.url` берётся путь без строки запроса (`req.url.split('?')[0]`), затем цепочка
   `if / else if` сравнивает пару «метод + путь». Ветка `else` возвращает 404.
4. **Функции `sendText` и `sendJson`.** Каждая задаёт код состояния (`res.statusCode`), заголовок `Content-Type`
   и завершает ответ вызовом `res.end(...)`. Заголовок содержит `charset=utf-8`, чтобы кириллица отображалась
   корректно. `sendJson` предварительно превращает объект в строку через `JSON.stringify`.
5. **Дата и время.** `formatDate` собирает строку формата `DD.MM.YYYY HH:MM`. Месяц берётся как `getMonth() + 1`,
   потому что в JavaScript месяцы нумеруются с нуля. Функция `pad` добавляет ведущий ноль через `padStart(2, '0')`.

## Обработка ошибок

Ответ 404 возвращается для любого неизвестного пути, а также для известного пути с методом, отличным от GET
(например, `POST /about`). Код 404 передаётся настоящим статусом ответа, а не только текстом в теле.

## Тестирование

Маршруты можно проверить в браузере (для GET-запросов), в Postman или через командную строку:

```bash
curl -i http://localhost:3000/api/student
curl -i http://localhost:3000/nope
```

В Windows PowerShell команда `curl` является псевдонимом другого командлета, поэтому нужно писать `curl.exe`:

```powershell
curl.exe -i http://localhost:3000/api/student
```

В работе создан HTTP-сервер на чистом Node.js. Изучено, как обработчик получает метод и адрес запроса, как задаются
код состояния и заголовки ответа, как возвращаются текст и JSON и как вести журнал запросов.

Ограничения подхода: маршрутизация через `if / else if` разрастается с числом маршрутов, нет разбора тела запроса,
нет middleware и разделения кода по слоям. Для известного пути с неподдерживаемым методом точнее был бы код
405 Method Not Allowed, но в этой работе такие запросы обрабатываются как неизвестные (404). Эти недостатки
устраняет Express.js в лабораторной работе №2.
